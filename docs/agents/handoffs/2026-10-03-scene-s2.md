# Task handoff: S2 modular object interaction and viewer commands

## Objective and scope

Complete the requested legacy scene/controller integration with move, rotate and
scale interaction in the native app. S1 was verified and committed separately as
`d90feb3812abe2795489f44d80e6385908d8c686` before this checkpoint began.

## Current state

`ObjectInteractionController` captures original geometry and transform parameters,
previews a matrix delta, and commits one atomic command at release. World-axis
moves use the focal plane, rotation edits Y and scale preserves axis ratios.
Ctrl snaps. Escape, navigation, workspace changes, project edits and replacement
outputs discard previews. Matching Transform provenance previews every affected
mesh without mutating published outputs. Stable selection remains workspace-only.

The generic SDK viewer command capability is optional and has no scene types.
Application adapters resolve execution targets to ordinary parameters or exposed
component controls. They reject stale revisions, missing/unexposed targets,
duplicate parameters and invalid ranges before changing history. Use viewers are
scoped to their selected component. Component snapshots and opaque content remain
intact. Numeric/data adapter tests link no scene libraries.

The new `scene-interaction-tool.smartflow` has a fresh component identity and all
transform controls exposed. The old scene-tool's contract is unchanged.
Camera/selection/controller/rendering modules stay in the scene extension; audited
legacy helpers and notices remain isolated in vendor. No legacy checkout is
referenced by build/runtime or modified.
