# W4: Browser scene workflow and interactive primitive viewer

## Objective and scope

Deliver required 3D capability alongside the independent data workflow, keeping
core/runtime domain-independent and native desktop primary.

## Current state

Scene nodes execute through browser SDK contracts with cloned geometry/material,
bounded scene validation and cancellation yielding. The app's orthographic canvas
viewer supports orbit, wheel zoom, framing and object selection. Camera state
persists in the browser namespace; portable native camera fields initialize it
without rewriting native JSON. Deliberate source-size edits use undoable project
commands. See [decision 0022](../../architecture/decisions/0022-browser-scene-preview.md).

## Verification

`npm.cmd run check`: formatting, type checks, 62 Node tests and production worker
build passed. Chromium scene interaction tested orbit/frame, object selection,
source edit/undo and camera download/reopen. The scene screenshot was inspected:
geometry, selected-object outline, graph and inspector are legible. Shared scene
coordinate fixtures exercise native/browser transform order and nonuniform scale.
Native Release CMake build passed; both relevant scene/startup CTest checks passed.
All seven Chromium regression checks passed, including the data workflow. After
the final wheel-listener/layout correction, scene interaction was rerun.

## Decisions and open questions

This is a bounded opaque primitive preview with fixed lighting, not a production
GPU renderer. Native manual packaged acceptance remains pending. No user browser
profile or live Windows interaction was automated.
